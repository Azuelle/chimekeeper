# ADR-005（网格）: 圆桌环布局 + 玩家卡

- 日期: 2026-09-07（改写，取代 2026-09-06 版「响应式满铺网格」结论）
- 状态: 已接受
- 关联: ADR-002（自由摆放推迟 v1.5 不变）、ADR-004（版权线）、ADR-011（锚号体系）

## 背景

v1 结论（两列满铺网格 + 卡片间连接线）在评审后修订：

1. 满铺网格没有"围坐"感——说书人的核心动线是环形（谁挨着谁，共情者/厨子/私聊）
2. 官方 botc.app 与中文官方魔典（clocktower.gstonegames.com）的交互范式是
   token 主体 + 名牌 + 点击弹菜单，国内玩家已有肌肉记忆
3. 连接线在满铺网格里无法表达邻座关系，属于补丁式方案

## 决定

### 布局：圆桌感座位环（2026-09-07 改写补充）

座位沿"围桌"的环**顺时针**排布（顶行左起 → 右 rail 向下 → 底行自右向左 →
左 rail 自下而上收回合拢到座位 1），编号 1..n 连续相邻，仅凭环本身表达邻座关系，
**不渲染连接线**。手机竖屏 2 列，平板/桌面按容器宽自适应 3–8 列；几何由纯函数
`ringLayout(count, cols)` 计算：

- **顶行铺满列宽**：座位 1 在左上角，1..C 向右占满整行（**无右上空格**）；
  左右 rail 等长 `L`，右 rail 从顶行右端正下方起；底行右对齐、阅读自右向左
  （整行 `C`，或收窄一格 `C-1`，尽可能省行）；四角最多只留左下角空。
- rail 长度取"底行能压到不超过列宽"的最小值：`L = ⌈(n−2C)/2⌉`（n≤2C 时为 0）。
- **列数 = 2 不搞圆角**（两列太窄、留空浪费，省空间优先）：偶数人数直接整行闭环，
  奇数人数末尾单座居左收底。

### 玩家卡（座位单元）

圆角矩形卡片：

- **左侧 token 主体**：左上角玩家编号（小字号）；首夜/非首夜行动顺序徽记分列
  左右（死亡后变灰）；token 圆环按实际阵营着色（`Seat.alignment`：
  good 蓝 / evil 红 / 未分配占位灰，v1 以 CSS 环色表达，图标着色待官方素材）；
  token 下方为名牌（默认空）
- **右侧提示标记区**（上下居中）：堆叠该座位的提示标记，空时显示
  「点击添加提示标记」占位
- **点击卡片弹出菜单**：编辑名字（内联文本框）、交换座位、平移座位（涟漪式：
  ABCD 选 A 移到 4 号位 → BCDA，链式 `swapOccupants` 实现，锚号与 displayOrder
  均不动）、移除座位（可选将编号放入复用池）；其余菜单项按里程碑门控
  （M2 角色类 / M3 死亡与提名类），未到里程碑时**置灰占位**并标注原因

### 素材红线（TPI 合规）

- token 圆环 / 帷幕 / 徽记 / 名牌全部**自绘简化版**；样式收拢在
  `src/ui/tokenSkin.ts`，组件只消费不写死——未来取得 TPI 官方素材许可后
  替换单一模块即可接入官方美术，卡片组件零改动
- **不使用集石（clocktower.gstonegames.com）OSS 素材**：非盈利不构成授权，
  外链亦属盗链；角色图标外链维持 bra1n 路线（ADR-004）
- 中文官方魔典仅参考交互模式与信息架构，**不复制其代码与样式**

## 后果

- 正面：环形语义回归；卡片信息密度适配说书人扫视（编号/阵营/状态一眼可见）；
  菜单为 M2/M3 功能预留了统一挂载点；里程碑门控使功能渐进可发现
- 负面：卡片比裸 token 宽，单屏容量略降；常用操作多一次点击（菜单换界面干净）；
  2 列窄屏为整行闭环（省空间但"环感"最弱，手机竖屏是主场景，可接受）
