# ADR-005（网格）: v1 魔典视图改用响应式网格布局（替代环形）

- 日期: 2026-09-06
- 状态: 已接受
- 取代: ADR-002 中"v1 用环形固定布局"的部分（"自由摆放推迟到 v1.5"的结论不变）

## 背景

ADR-002 出于实现复杂度考虑选择了环形固定布局。Sierra 提出替代方案：
用矩形网格替代环形，小屏上自然塌成两列——即集石官方小程序魔典的形态，
国内玩家已有使用习惯。

进一步分析后确认网格布局在多个维度优于环形：

- **触控**：环形在小屏 + 高人数（12-15 人）时 token 可点击区域过小
- **习惯迁移**：两列网格 = 国内玩家已熟悉的官方小程序形态，零学习成本
- **编号阅读顺序**：网格从左到右从上到下，无环形"从哪开始数"的歧义，契合编号文化
- **实现成本**：CSS Grid 自适应列数 vs 环形的三角函数定位，前者更简单、
  AI 实现质量更稳、响应式免费获得

环形被牺牲的代价及缓解：

- **邻座关系**（共情者/厨子/说书人私聊动线依赖"谁坐谁旁边"）：
  座位卡之间渲染连接线，末位连回首位，明确表达环形语义；
  编号本身加大加粗作为主要识别手段
- **视觉重心**：环形天然有圆心可放全局状态；网格改为顶部"舞台区"
  承载当前阶段/夜晚指示/被提名者等信息

## 决定

v1 魔典视图采用响应式网格：CSS Grid + `auto-fill/minmax`，
手机竖屏两列、平板三列、桌面四列以上；座位卡含大号编号 + 角色 token
（说书人视角）+ 提示 token + 生死状态；座位间连接线表达环形邻座关系。
自由摆放仍推迟至 v1.5（ADR-002 该部分结论不变）。

## 后果

- 正面：移动端体验显著提升；实现与测试成本下降；符合国内用户习惯
- 负面：视觉上不如环形有"围炉夜谈"的仪式感；邻座连接线在高人数时
  可能显得杂乱（届时评估是否默认收起）
