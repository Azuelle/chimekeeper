# ADR-011（锚号）: 座位号 = 不可变椅子锚点，物理位置独立，换位 = 原子交换住户

- 日期: 2026-09-06
- 状态: 已接受

## 背景

线下真实需求（用户实测自粿条会长小程序的痛点）：

1. **女舍监**（旅行者）每晚让两名玩家互换座位——需要换位功能；竞品实现有
   状态不同步 bug，根因是座位号/玩家状态归属混乱
2. **旅行者中途加入**且玩家不想重排队：出现 1 2 3 4 **15** 5 6 … 14 的
   非连续编号排列——编号与物理位置天然解耦
3. 玩家中途离场需要删座位，但历史事件（谁被提名、谁死了）仍引用其编号

## 决定（不变量）

1. **seatNumber = 椅子锚点，只增不改**：
   - 新座位（旅行者加入等）编号默认 = 当前最大号 + 1（15 号插在 4 和 5 之间坐着，但编号永远是 15）
   - 座位移除后编号默认**退役**，本局内不复用（避免历史事件引用歧义）
   - **2026-09-07 修订**：退役编号可经显式操作（移除时勾选「编号放入复用池」、
     或「启用退役编号」批量并入）回到 `Game.reusePool`，此后 `addSeat` 优先消费
     池中最小号，池空才走高水位；`seatHighWater` 只增不减，历史事件引用仍不歧义
2. **displayOrder = 物理位置**（网格/座位圈中的显示顺序），与编号无关；
   换位/增删只改 displayOrder 排列
3. **换位 = 原子交换两个座位的全部"住户"字段**（昵称/角色/生死/票 token/
   提示标记/旅行者标记），seatNumber 与 displayOrder 不动——号跟着椅子走，
   人换椅子，一切引用零失效
   - **2026-09-07 补充**：涟漪平移 = 沿 displayOrder 环逐邻链式调用换位
     （起点住户移到终点，中间住户顺延，`lib/seats.rippleShift`，ADR-005 玩家卡）
4. 换位/增删座位各自生成结构化事件（seat_swap / seat_add / seat_remove），
   复盘时间线完整还原物理动线
5. store 层的换位必须是单一 action（一次事务写库），不做分步状态更新——
   这是竞品 bug 的直接教训

## 后果

- 正面：女舍监从数据层就不可产生状态不同步；非连续编号免费支持；
  历史事件永不失效；说书人中途修正摆错座位也用同一原语
- 负面：编号非连续（15 夹在 4、5 间）需要 UI 明显展示编号；displayOrder
  从 v0.5 就必须是显式字段（已加），v1 无迁移成本
