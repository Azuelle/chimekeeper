# ADR-012（扫码）: 角色列表分享 = 同源静态页 + PWA 缓存，不做实时同步

- 日期: 2026-09-06
- 状态: 已接受

## 背景

需求：学 Pocket Grimoire 让玩家扫码打开动态角色列表网页。担心网络波动。
先拆开"网络"到底是什么：

| 场景 | 依赖 | 波动敏感度 | 本项目方案 |
|---|---|---|---|
| 玩家首次打开链接 | 网络（HTTPS 到自托管） | 一次性，可预加载 | PWA cache-first 壳 |
| 页面加载完成后 | **零** | 零 | 内容全部内联/预渲染，无任何后续请求 |
| 阵容中途变化要更新 | 网络重推 | 高（每个玩家重扫） | **v1 不做实时同步**（见决定 4） |

关键洞察：角色列表页是**纯内容页**（无 JS 状态机、无交互逻辑），加载完成后
断网也能看——这和 Pocket Grimoire 的方案一致（它的分享链接也是一次性内容，
非实时房间）。

## 决定

1. **分享链接 = 同源静态路由** `/share/:token`，由自托管实例服务。
   token 是一局一个的短随机串（如 6 位），分享页**只暴露脱敏内容**：
   角色名 + 一句话能力 + 阵营徽标（蓝/红/旅行等）。无座位号、无玩家昵称、
   无真实分配——保密由"不写入"而非"隐藏"保证
2. **渲染预烘焙**：说书人点"生成分享"时，在本地把当前剧本/已确认的抽袋构成
   渲染成静态 HTML 片段存 IndexedDB；路由命中后秒出（<100ms），
   Service Worker 的 cache-first 策略让整个壳离线可重开
3. **局内波动零影响**：玩家打开页面后即使全场断网也照常浏览（纯静态 +
   SW 缓存）；说书人端改阵容只在下次生成时反映，已打开的页面不自动变
4. **v1 明确不做实时同步**（WebSocket/SSE/轮询全部否决）：
   - 违反 local-first 红线（ADR-001/PRD Won't：不建服务端状态）
   - 线下局网络不可靠（商场地下室/朋友家弱 Wi-Fi），实时同步的失败模式
     比"需要重扫"恶劣得多
   - 阵容变化（旅行者加入等）低频，重扫二维码成本可接受
5. **兜底**：二维码图片本地生成（已选型 qrcode 库），说书人可截图发群
   作为"冷备份"；即使自托管挂了，群里截图仍可看

## 后果

- 正面：分享页加载一次后永久离线可看；无服务端状态；说书人手机熄屏
  玩家端不受影响；符合 TPI（无账号无联机）
- 负面：阵容变化需玩家重扫（缓解：二维码生成即时，说书人把新码亮给全场）；
  依赖自托管实例在线（缓解：截图兜底）
