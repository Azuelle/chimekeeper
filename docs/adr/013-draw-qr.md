# ADR-013（抽码）: 盲抽袋数字化 — QR 码 + 盐 + HMAC 防篡改，方案 A 原码永有效

- 日期: 2026-09-06
- 状态: 已接受

## 背景

线下盲抽袋实体化：玩家闭眼从袋中摸角色标记。数字化复刻需满足：
1. 玩家肉眼无法提前知道内容（QR 码天然满足）
2. 防篡改（玩家修改 roleId 后应显示无效）
3. **零网络通信**（Zerotier/弱网/地下室场景，玩家手机可能完全连不上说书人设备）

Pocket Grimoire 实体流程参考（截图确认）：玩家按座位顺序（从 1 号开始）传递 iPad，
从背朝上的 token 里随机选取一个，点击后显示自己（认知的）角色，同时填写昵称，
看完后返回背朝上页面，将设备传给下一位；已选 token 置灰不可再点击。
**关键设计**：点击顺序对应初始座位位置；抽取完成后角色已放置在魔典中，
只是被抽牌页面覆盖看不见；**中途关闭抽牌页面会导致无法继续抽取**（状态未持久化）。

## 决定

1. **payload 结构**：`{ roleId, nonce, hmac }`，nonce 为 32 字符随机盐，
   HMAC = HMAC(roleId + nonce, key = gameId)。篡改 roleId 后校验失败 → "无效码"
2. **方案 A：原码永有效**。nonce 仅作盐用，不实现"一次性"——玩家保存原码重扫
   依然显示角色。理由：说书人在场是最大反作弊；作弊毁掉的是作弊者自己的游戏体验；
   零通信设计下"作废"无法真正落地（离线设备无法知道全局状态）
3. **显示节奏**：即抽即看——玩家扫 QR 码 → 手机本地解析显示角色 → 可填写昵称 →
   返回背朝上页面传给下一位。**无"说书人确认"环节，无玩家→说书人通信**
4. **座位顺序映射**：QR 码按座位顺序生成（1 号→2 号→…），玩家按座位顺序传递设备；
   抽取完成后角色已绑定座位（锚号体系），只是 UI 层被抽牌页面覆盖
5. **状态持久化**：抽取进度（已抽/未抽）实时写入 IndexedDB，中途关闭页面重开可继续——
   修复 Pocket Grimoire 的已知 bug
6. **实色/模糊分层**（学 Pocket Grimoire）：
   - 玩家该看的（角色展示、文字说明）：**实色背景**，完全遮挡背后魔典
   - 说书人该看的（魔典、抽袋管理）：**高斯模糊背景**，可隐约感知但看不清细节
7. **与实体token共存**：说书人可选"发码"或"实体袋"两种模式，不强制

## 技术实现

- QR 码生成：说书人设备本地（qrcode 库），无需网络
- 玩家手机：扫码 → 本地解析 JSON → 校验 HMAC（gameId 嵌入链接作为盐）→ 显示角色
- 状态：抽取进度 + nonce 记录在说书人设备 IndexedDB，中途关闭可恢复
- HMAC 密钥：gameId 嵌入 QR 码链接，玩家手机本地计算比对，无需在线查询

## 后果

- 正面：零道具成本；随机性密码学可验证；HMAC 防篡改；**认知覆盖与实体一致**
  （酒鬼抽士兵 token，说书人事后挂标记）；**完全离线**，Zerotier/弱网场景完美工作；
  即抽即看 + 座位顺序传递与 Pocket Grimoire 一致；实色/模糊分层防窥屏；
  状态持久化修复 Pocket Grimoire 关闭页面 bug
- 负面：玩家可保存原码重扫（接受：说书人在场是最大反作弊，作弊毁掉的是自己体验）；
  需要每个玩家有手机且能扫码；实体局的"摸袋仪式感"部分流失
