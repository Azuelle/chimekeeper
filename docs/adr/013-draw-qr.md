# ADR-013（抽码）: 盲抽袋数字化 — QR 码 + 盐 + 一次性，纯本地零通信

- 日期: 2026-09-06
- 状态: 已接受

## 背景

线下盲抽袋实体化：玩家闭眼从袋中摸角色标记。数字化复刻需满足：
1. 玩家肉眼无法提前知道内容（QR 码天然满足）
2. 防玩家解码/篡改/重扫
3. **零网络通信**（Zerotier/弱网/地下室场景，玩家手机可能完全连不上说书人设备）

Pocket Grimoire 实体流程参考（截图确认）：玩家拿到说书人的 iPad，从背朝上的 token 里
随机选取一个，点击后显示自己（认知的）角色，同时填写昵称，看完后返回背朝上页面，
将设备传给下一位；已选 token 置灰不可再点击。**全程在说书人设备上完成，无玩家手机参与**。

本项目的抽码实现：说书人设备生成 QR 码展示给玩家扫，玩家手机本地解码显示角色，
**无需与说书人设备通信**。防作弊靠 QR 码内容本身（盐 + HMAC），不靠在线状态校验。

## 决定

1. **payload 结构**：`{ roleId, nonce, hmac }`，nonce 为 32 字符随机盐，
   HMAC = HMAC(roleId + nonce, key = gameId)。篡改 roleId 后校验失败 → "无效码"
2. **一次性**：nonce 记录在**说书人设备本地**（非玩家手机），扫过的 nonce 在说书人端
   标记已用；玩家手机**不存储状态**，重扫时由说书人设备判断是否允许
3. **显示节奏**：即抽即看——玩家扫 QR 码 → 手机本地解析显示角色 → 可填写昵称 →
   返回背朝上页面传给下一位。**无"说书人确认"环节，无玩家→说书人通信**
4. **传 iPad 模式**：说书人将手机/平板传递给玩家轮流抽取；玩家屏幕较小，
   方便避免身边人窥屏
5. **重扫机制**：玩家没扫到/想重扫 → 点击已选 token → 说书人设备重新生成
   新 QR 码（新 nonce，原 nonce 已作废）→ 玩家扫新码。**重扫生成新码，非展示原码**
6. **与实体token共存**：说书人可选"发码"或"实体袋"两种模式，不强制

## 技术实现（零通信方案）

- QR 码生成：说书人设备本地（qrcode 库），无需网络
- 玩家手机：扫码 → 本地解析 JSON → 校验 HMAC（gameId 硬编码在说书人分享的
  链接里，玩家手机本地校验）→ 显示角色。**全程离线**
- 状态同步：nonce 已用状态只在说书人设备（生成/重扫时查询），玩家手机无状态
- HMAC 密钥：gameId 作为盐，嵌入 QR 码链接（如 `/draw/:gameId/:nonce#hmac`），
  玩家手机从链接解析 gameId 后本地计算 HMAC 比对，无需在线查询

## 后果

- 正面：零道具成本；随机性密码学可验证；防作弊强于实体袋（实体袋可被摸牌手法作弊）；
  **认知覆盖（酒鬼/疯子/提线木偶）与实体一致**——抽到的就是认知后角色 token（如士兵），
  说书人事后挂"是酒鬼"标记即可；**完全离线**，Zerotier/弱网/地下室场景完美工作；
  即抽即看 + 传设备模式与 Pocket Grimoire 实体流程一致，玩家零学习成本
- 负面：需要每个玩家有手机且能扫码；实体局的"摸袋仪式感"部分流失；
  玩家手机需能解析 QR 码（现代手机原生支持，无 App 依赖）
