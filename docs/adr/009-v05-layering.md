# ADR-009（v0.5）: 版本分层 — v0.5 自用内测版 → v1 线下完整版

- 日期: 2026-09-06
- 状态: 已接受

## 背景

线下局的现实：15+ 人局几乎必有旅行者（>15 人强制），失败上帝/地狱图书管理员等
传奇角色是高频主持工具 → 旅行者+传奇+奇遇（F-17）必须进 v1，否则线下不完整。
但等 F-17 全做完才能开玩会推迟第一次真实测试。需求讨论结论：先出 v0.5。

## 决定

版本分层：

- **v0.5 内测** = M1 开桌 + M2 入夜 + M3 天亮的功能闭环
  （读剧本/排座位/抽袋(默认+提示)/夜单/计票/流水/战报），
  不含旅行者/计时器/备忘/声称。**自用，拿真实线下局压测**
- **v1 线下完整版** = v0.5 + F-17 旅行者（旅行者座位/中途加入/阵营计算排除）+
  F-21 计时器 + F-19 备忘(自由文本版) + F-20 声称 + F-09 PWA/F-10 双语完善
- 里程碑相应调整为 M1→M2→M3(=v0.5)→M4 补全→M5 上线

F-17 从 Could(v2) 提到 Must(v1)；其数据模型影响（Seat.isTraveler、
阵营计算排除旅行者）在 v0.5 的类型定义中就预留字段，避免 v1 迁移。

## 后果

- 正面：第一次真实局测试提前约 2-3 周；旅行者需求不再挤压核心闭环
- 负面：v0.5 阶段类型带预留字段（可空 isTraveler），略增复杂度
