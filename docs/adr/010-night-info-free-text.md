# ADR-010（备忘）: 夜晚信息记录 v1 用自由文本填空，结构化推迟 v2

- 日期: 2026-09-06
- 状态: 已接受

## 背景

粿条会长小程序可记录夜晚给玩家的信息（如侍女选两名玩家得知"2"），这些信息
不以 token 形式进魔典，但复盘价值高。结构化实现的困难：

1. 每个角色的信息形态不同（数字/是-否/角色标记/方向/玩家），无现成结构化数据源
2. 结构化 = 只支持内置库角色，DIY 角色无法覆盖
3. 工作量集中在文案/模板维护，与核心闭环竞争时间

## 决定

1. **v1 自由文本填空**：提供快捷模板「座位号【角色名】___」（如 `5号小李【侍女】__`），
   说书人填空后存为 note 类事件（F-06 流水）。模板纯 UI 层便利，不新增数据结构，
   天然支持 DIY 角色和任何剧本
2. **v2 结构化**：内置官方角色的信息格式模板（侍女→数字、占卜师→是/否）；
   同时设计自定义扩展字段 `infoTemplate`（剧本 JSON 中声明，供 DIY 剧本作者
   自行为角色描述信息形态），DATA-MODEL 届时登记
3. 战报（F-08）聚合时按座位归组全部备忘

## 后果

- 正面：v1 零新增数据模型即可落地；DIY 角色无死角；说书人负担最小
- 负面：v1 无法对备忘做统计查询（如"共情者全部读数"）；v2 时需迁移历史
  note 事件的解析（宽松解析，不强制）
