# ADR-006: 夜晚面板采用"系统锚点步骤 + 角色步骤"双层结构

- 日期: 2026-09-06
- 状态: 已接受

## 背景

调研官方 wiki Setup 与中文钟楼百科「规则概要」「夜晚行动顺序一览」后确认：
实体版夜晚流程并非纯角色排序，而是**结构性系统步骤**（黄昏 → 首夜的爪牙信息/
恶魔信息 → 角色行动 → 黎明）与角色步骤交织。bra1n 格式的 firstNight/otherNight
数值只覆盖角色，系统步骤需工具自行内置。此外罂粟种植者、魔术师、遗忘之门等角色
会改写系统步骤本身。

原设计（`nightOrder.ts` 仅按数值排角色）会漏掉这些步骤——这正是"失败的上帝"
的高发区（忘了给恶魔展示伪装、忘了爪牙互认）。

## 决定

1. 夜晚面板 = 系统锚点步骤（内置、固定）+ 角色步骤（按剧本数据排序）的合并清单：
   - 首夜：黄昏 → 爪牙信息（≥7人）→ 恶魔信息（≥7人）→ 角色步骤 → 黎明
   - 其他夜晚：黄昏 → 角色步骤 → 黎明
2. 系统步骤在数据层建模为 `NightStep` 类型（union：system | role），
   使面板渲染与事件记录统一
3. 角色对系统步骤的改写（如罂粟种植者跳过恶魔信息）：v1 仅展示提示文案，
   不自动改写流程（避免滑向规则裁决，见 PRD Won't 清单）
4. 中文百科调整版夜晚顺序暂不作为数据源（见 docs/reference/night-order-cn.md
   的采用策略），v2 再评估

## 后果

- 正面：覆盖"忘记爪牙/恶魔信息"这类最常见说书事故；夜晚面板成为完整的
  流程 checklist 而非半成品
- 负面：`buildNightOrder` 签名变化（返回 NightStep[] 而非角色数组）；
  系统步骤的提示文案需要 i18n（但不来自剧本 JSON，是 UI 内容）
