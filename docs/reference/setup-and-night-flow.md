# 参考：实体版游戏运作流程（Setup + 夜晚/白天流程）

> 来源：英文官方 wiki [Setup](https://wiki.bloodontheclocktower.com/Setup)（2023-04）、
> [Storyteller Advice](https://wiki.bloodontheclocktower.com/Storyteller_Advice)（2024-11）、
> 中文钟楼百科[「规则概要」](https://clocktower-wiki.gstonegames.com/index.php?title=规则概要)（2023-03，与英文 Setup 对应并扩展了夜晚/白天/结束全流程）。
> 本文档是设计与数据模型的规则依据，不是用户文档。

## 一、初始设置十步（对应 F-01/F-02/F-03 的实现依据）

1. **召集玩家**：座位围成圆或方，明确顺时针座次；说书人需留进出空隙
2. **准备魔典**：实体版=组装魔典+支架；**数字版=我们的魔典视图**
3. **选择剧本**：将剧本的夜晚顺序表置于魔典右侧 → **对应我们的剧本导入 + 夜晚面板**
4. **准备城镇广场**：生命标记对应座位、投票标记堆中央、旅行者列表展示镇民/外来者/爪牙**数量** → **对应 F-02 座位圈 + 阵营构成展示**
5. **给新玩家宣读规则**（线下人肉环节，工具不管）
6. **秘密选择角色**：按人数从剧本选镇民/外来者/爪牙/恶魔 → **F-03 盲抽袋**
   - >15 人时超出者自愿成为旅行者（v2 F-17）
   - 官方建议新手首局不加旅行者/传奇
   - 官方给了三套 8 人推荐配置（可作 F-14 内置剧本的参考）
7. **添加/移除角色**：带橙色花瓣（`setup: true`）的角色改变构成，如 Baron [+2 外来者] → **已实现于 `setup.ts: adjustedComposition`**
8. **向魔典添加提示标记**：角色标记顶部绿叶数 = 该角色提示标记数 → **数据模型的 `reminders` 数组**
9. **分发角色**：洗混入盲抽袋，玩家依次抽取，秘密查看 → **F-03 盲抽袋动画的实体原型**
10. **角色标记放入魔典**：与座位位置对应；顺序（顺/逆时针）必须与现实一致；同坐沙发者可靠近分组 → **ADR-005 网格布局的连接线+分组扩展空间**

## 二、夜晚阶段（对应 F-04 的实现依据）⚠ 重要

### 夜晚结构 = 系统步骤 + 角色步骤交织

中文「规则概要」给出的完整夜晚流程：

1. **准备夜晚**（说书人事先筹划，玩家自由讨论）：
   - 选夜晚顺序表正确一面（首夜 / 其他夜晚）
   - 按需添加/移除提示标记与夜晚标记
   - **筹划**：想好今晚给恶魔展示哪三个伪装、给酒鬼什么假信息——"提前确定有助于加快节奏"
2. **黄昏（Dusk）**：全员闭眼；部分旅行者/传奇/奇遇角色此时行动
3. **首夜专属：爪牙信息（Minion Info）**：7 人及以上局，同时唤醒所有爪牙，展示"他是恶魔"信息标记并指认恶魔
4. **首夜专属：恶魔信息（Demon Info）**：唤醒恶魔，展示"他们是你的爪牙"并指认；展示"这些角色不在场"+**三个不在场善良角色作为伪装**
   - 官方建议伪装组合：两个镇民 + 一个外来者
5. **按夜晚顺序表依次唤醒角色行动**，结算能力、放置提示标记
   - 夜晚顺序表上角色旁的**紫色圆点** = 可能需要放置该角色的提示标记
   - 有标记 ≠ 必唤醒：按实际情况判断（如守鸦人只在被杀时唤醒）
6. **黎明（Dawn）**：等待 5–10 秒（防止玩家反推最后行动者）→ 全员睁眼 → 宣布死亡与复活（不公布原因）

### 会改写夜晚结构的角色（数据模型必须能表达）

- **罂粟种植者**在场 → 跳过爪牙信息和恶魔信息环节
- **魔术师**在场 → 爪牙/恶魔信息环节内容需调整（爪牙不知谁是恶魔）
- **遗忘之门**加入 → 跳过爪牙信息和恶魔信息
- **告密者** → 爪牙信息时向爪牙展示三个不在场善良角色
- **落难少女** → 对爪牙暴露（中文百科已将其首夜行动调整至爪牙信息环节内）
- **国王/提线木偶/书生** → 对恶魔暴露，恶魔信息环节一并展示

### 夜晚手势体系（说书人参考，工具不实现但可作为帮助页内容）

睁眼=拍肩/膝两下；闭眼=手遮眼；是=点头；否=摇头；善=拇指上；恶=拇指下；
数字=手指比划；选玩家=指向（说书人应**垂直下指确认**目标，防误选）。
——来源：英文 Rules Explanation + Storyteller Advice「confirm choices with a downward finger point」

## 三、白天阶段（对应 F-05 的实现依据）

- **提名限制**：同时只有一项提名在进行；仅存活玩家可发起提名；每人每天发起≤1 次、被提名≤1 次
- **辩护**：投票前给被提名者 10–30 秒
- **计票**：说书人站中央，从被提名者开始顺时针转圈数票；举手=票
  - 存活玩家每天可投任意多次
  - 死亡玩家全局只剩 **1 票**（投票标记，用掉即无）→ 数据模型 `Seat.hasVoteToken`
- **通过条件**：票数 ≥ 存活人数一半（`vote.ts` 已实现）**且为当日最高票（不得并列）**
  - ⚠ 并列规则：后来者与"即将被处决者"平票 → **双方都不处决**；之后须超过平票数
  - 这是 `vote.ts` 目前只判 half 而**未实现的"当日最高票"追踪**——F-05 实现时需加一个"当前待处决者+其票数"的白天状态
- **处决**：每日最多 1 人；宣布死亡（或"被处决但未死亡"，如弄臣/水手）；处决完白天结束
- **死亡效果**：生命标记翻面+放投票标记；魔典中角色标记放帷幕标记；失去能力；不能提名；角色**不公开**

## 四、胜负判定（对应 F-08 结局登记）

- 善良胜：所有恶魔死亡（注意红唇女郎/多恶魔/善良恶魔等复杂情况——**工具只登记结果不做判定**，符合 Won't 清单）
- 邪恶胜：只剩 2 名存活玩家（旅行者不计）
- 同时达成 → 善良胜
- 说书人可提前宣告确定局（如全邪恶存活），但须判断败方是否仍有任何理论胜算

## 五、对我们设计的直接影响清单

1. **夜晚面板必须包含系统步骤**：黄昏 / 爪牙信息 / 恶魔信息 / 黎明，与角色步骤穿插 → 数据模型修订（见 DATA-MODEL.md 夜晚面板一节）
2. **投票需要"当日最高票"状态机**，不只是单次过半判定
3. **恶魔伪装推荐默认策略**：2 镇民 + 1 外来者（`setup.ts` 可优化）
4. **夜晚筹划提示**（给恶魔的伪装、给酒鬼的假信息）可以作为首夜面板的引导文案
5. 说书人失误处理哲学（继续游戏、承认但不详述、私下补结算）→ 复盘 note 事件的官方背书
