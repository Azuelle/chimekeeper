# 参考：粿条会长小程序复盘输出实例分析

> 来源：用户提供的四局实录（剧本名如“上帝出席”“信口雌黄”）。
> 用途：校准 F-08 战报的输出形态，发现数据模型缺口。

## 一、复盘输出形态（直接校准 F-08 战报）

粿条长图的结构 = 魔典快照（座位圈 token 布局，⚠不是网格）+ 逐夜逐天时间线。
可复用的排版语言：

- **双标题分段**：`第 N 夜 / Night N`、`第 N 天 / Day N`
- **每条事件行 = 角色icon + 玩家(实际角色)[获得能力] + 动作 + 结果**
  如：`🧪懒洋洋(炼金术士)[科学怪人]获得了科学怪人的能力`
- **死亡原因链**：`死于处决了` / `因 星野(维齐尔)而死于处决了`（带归因）
- **状态词缀**：`🪑(村夫)🍺 选择了…`（醉酒徽标随事件显示）
- **结算行**：`当前场上一共有 N 名存活玩家`、`昨天夜里，死亡的玩家是 X、Y`、
  `善良阵营获胜🎉`/`邪恶阵营获胜🎉`（含 emoji）
- **自由文本插入**：说书人/玩家发言以独立段落混在事件流中
  （如"菜菜子说按自己逻辑盘出场上有4个外来者"）

## 二、事件词汇表（实测高频，F-06/F-08 覆盖清单）

| 短语模式 | 对应事件 | 现状 |
|---|---|---|
| X 提名了 Y，该玩家获得了 N 票 | nomination + vote | ✅ |
| X 死于处决了 / 被处决，但不会死亡（维齐尔） | execution | ✅（但需"不死亡"变体） |
| X 选择了 Y，Y 死亡了 / X 获得了某角色能力 | night_death + night_action | ✅ |
| X 声称自己是 Y / 声称得知了… / 声称发表了… | claim（含 claimRoleId + 声明内容） | ✅ F-20 |
| X 中毒了 / X 恢复健康了 | **状态变体事件** | ⚠ 缺 |
| X 现在是小恶魔（女巫转化） | **角色变更事件** | ⚠ 缺 |
| 说书人假装某角色在场，决定了：…（禁卫军） | **禁卫军/ST 公开裁决** | ⚠ 缺 |
| 由于选中善良玩家，今晚不会再有其他玩家死亡 | **规则注释行** | ⚠ 缺（note 可承载） |
| X 与 Y 剪刀石头布，Z 输了 / 成功复仇 | 特殊结算（可承载于 note） | ✅ note |

## 三、暴露的数据模型缺口（v1 需补）

1. **`role_change` 事件**：女巫→小恶魔、堤丰之首能力转移等"同座位换角色"
   （锚号体系天然支持：住户字段变更 + 事件记录，displayOrder/seatNumber 不动）
2. **状态变体事件**：中毒/醉酒/恢复健康——不是 note 而是结构化事件（可标记于
   `ReminderToken` 增删，复盘时按"🍺"等徽标渲染）
3. **禁卫军/ST 公开裁决**：`st_decree` 事件（"说书人假装 X 在场，决定了：明天
   疯狂想死的玩家可能会被立即处决"）——对无神论者局是核心叙事
4. **存活数结算行**：每天/夜结束自动汇总"当前场上一共有 N 名存活玩家"（排除旅行者）
5. **恶魔伪装以"[获得能力]"方括号语法渲染**（战报模板细节）

## 四、不抄的部分

- 复盘长图布局粿条用**座位圈**，但我们已决定网格（ADR-005）；战报导出用 Markdown
