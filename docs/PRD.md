# PRD — 司钟 产品需求文档

> 本文件回答"做什么、不做什么、做到什么程度算完"。
> 每个功能有唯一编号（F-xx）+ 速记名，实现与测试用例引用编号，聊天/commit 用「名字+编号」（如 F-03 抽袋）。
> 全部编号与速记名对照表见 [GLOSSARY.md](GLOSSARY.md)。
> 分级：**Must** = v1 必需 / **Should** = v1.5 / **Could** = v2 / **Won't** = 明确不做。

## 1. 产品定位

面向线下说书人的一站式工具：游戏运行辅助（魔典 + 夜晚顺序）+ 结构化过程记录 + 复盘导出。
目标用户：在内地组织线下局的血染钟楼说书人（玩家多为狼人杀背景，习惯编号发言）。

## 2. 核心场景（User Story）

**US-1 开局**：说书人拿到玩家自发分享的剧本 JSON（微信文件/剪贴板）→ 导入 → 输入玩家人数 → 系统按官方人数表给出阵营构成 → 盲抽袋随机分配角色 → 生成带编号的座位圈。

**US-2 夜晚**：魔典视图显示每个座位的角色与提示 token；夜晚面板按 firstNight/otherNight 顺序列出"该唤醒谁"，逐项打勾；夜晚死亡在黎明时登记。

**US-3 白天**：提名 → 投票（计票）→ 处决登记；说书人可随手记备注（口误修正、精彩发言）。

**US-4 复盘**：游戏结束选胜负 → 一键生成时间线复盘（Markdown 文本 / 长图），可直接发到群里。

**US-5 断线恢复**：说书中途微信/浏览器被杀后台 → 重开 → 状态完整恢复。

## 3. 功能清单

### Must（v1）

**F-01 读剧本** — 剧本 JSON 导入（宽松解析 + 角色注水）
- (a) 粘贴文本 / 上传文件 /  URL 三种方式导入 bra1n 格式剧本
- (b) 含未知自定义字段（logo、almanac 等）时正常导入，warning 面板提示
- (c) 角色缺必需字段且内置库无法补全 → 中文错误提示，指明角色名与字段名
- (d) `fixtures/` 下全部样本（含 botcscripts 纯 ID 格式）可导入（测试强制）
- (f) 纯角色 ID 剧本（官方 script tool / botcscripts 生态）自动从内置官方角色库注水：补全阵营/夜晚顺序/提示标记，剧本自带数据优先，每个注水角色记 info warning（ADR-007）
- (g) 角色 ID 双写法（`fortuneteller` / `fortune_teller`）规范化等价匹配
- (e) 解析后展示角色列表（按阵营分组）与相克规则

**F-02 排座位** — 座位与编号
- (a) 5–15+ 人座位圈，编号 1..n 顺时针
- (b) 昵称可填可不填，全程以编号为主键引用
- (c) 座位圈为响应式网格固定布局：手机竖屏两列（同官方小程序形态）、平板/桌面自动增列；座位间连接线表达邻座关系（v1 不可拖拽，见 ADR-002/005）

**F-03 抽袋** — 角色随机分配（ADR-008）
- (a) 显示官方人数表默认构成；在场 setup 角色高亮并附调整方向一句话（如 男爵「+2外来者 -2镇民」、隐士「-0~1外来者 +镇民」）
- (b) 说书人手动 +/- 各类型数量，实时显示袋内构成；总数 ≠ 玩家数时醒目警告但不阻止
- (c) 从剧本角色池随机抽取并分配，附带洗牌动画
- (d) 说书人可手动换角/重抽
- (e) 恶魔伪装自动推荐 + 手动修改，默认策略 2 镇民 + 1 外来者

**F-04 夜单** — 夜晚顺序面板
- (a) 面板 = 系统锚点步骤（黄昏/首夜爪牙信息/首夜恶魔信息/黎明，≥7 人才含信息步骤）+ 按在场角色 firstNight / otherNight 排序的角色步骤（ADR-006）
- (b) 每项显示角色名、座位号、官方提示词（reminder 文本）
- (c) 逐项打勾，进度本地持久化
- (d) 首夜与其他夜晚区分展示；夜晚间自动推进 round

**F-05 计票** — 白天流程记录
- (a) 提名：记录 提名者编号 → 被提名者编号
- (b) 投票：输入票数，自动判断是否过半（存活人数/2 向上取整）
- (c) 处决登记（含"处决但未死亡"如弄臣）
- (d) 死亡登记（夜晚死亡 / 任意时间），死亡后投票权状态切换

**F-06 流水** — 事件日志
- (a) F-04/F-05 的操作自动生成结构化事件（类型见 DATA-MODEL.md 枚举）
- (b) 时间线视图：按 round + phase 分组可读展示
- (c) 自由备注事件（note）
- (d) 事件可删除/修正（说书人总会记错）

**F-07 保险** — 本地持久化与恢复
- (a) 全部对局状态存 IndexedDB，任何时刻杀后台可恢复
- (b) 多对局管理：历史对局列表、只读查看、删除

**F-08 战报** — 复盘导出
- (a) 游戏结束登记胜负与原因
- (b) 导出 Markdown 复盘：座位表（编号+角色）+ 按轮时间线 + 结局
- (c) 复制到剪贴板 / 下载 .md 文件

**F-09 离线** — PWA
- (a) 可"添加到主屏幕"
- (b) Service Worker 缓存全部静态资源，断网可开局
- (c) 移动端（手机竖屏）可用为优先设计目标

**F-10 双语** — i18n
- (a) UI 文案 zh-CN 默认、en 完整 fallback
- (b) 所有文案走 i18n key，无硬编码

**F-23 扫码** — 角色列表分享（v1，ADR-012）
- (a) 说书人生成二维码，玩家扫码打开 /share/:token 静态页（角色名+一句话能力+阵营徽标）
- (b) 脱敏：只暴露剧本角色池，不含座位号/昵称/真实分配
- (c) 加载一次后离线可看（PWA cache-first + 预烘焙内容）；阵容变化需重扫，不做实时同步
- (d) 二维码截图发群兜底（自托管挂时）

**F-24 抽码** — 盲抽袋数字化（v1，ADR-013/014）
- (a) 每个角色生成 QR 码，payload 含盐+HMAC 防篡改（方案 A：原码永有效，不防重扫——说书人在场是最大反作弊）
- (b) 即抽即看 + 填昵称 + 传设备模式，复刻 Pocket Grimoire 实体流程
- (c) 离线模式：data URL 单角色页（零网络，Zerotier/弱网兜底）
- (d) 实色/模糊分层：玩家页实色遮挡，说书人页高斯模糊
- (e) 状态持久化：抽取进度实时写 IndexedDB，中途关闭可恢复

**F-26 指定发牌** — 说书人指定分配（v1，ADR-016）
- (a) 园丁/悟道者/无神论者等场景：说书人预先指定每个座位的角色
- (b) 发牌翻页：按座位顺序逐个展示 QR 码，扫完点"下一个"
- (c) 防呆：往回翻页时 spoiler 高斯模糊 + "这个角色已经分发过了，确定要再次展示吗？"确认

### Should（v1.5）

- **F-11 自由魔典** — 自由摆放视图（拖拽 token、提示 token 任意位置）— ADR-002
- **F-12 长图** — 复盘长图导出（Canvas 渲染，适配微信分享）
- **F-13 教学** — 新手引导（首次使用分步教学）
- **F-14 书架** — 剧本库：本地保存多个剧本、内置官方三版（ADR-015）
  - (a) 内置暗流涌动/黯月初升/梦殒春宵，开箱即用零导入
  - (b) **官方全角色池模式**（F-25）：181 角色全量可抽，支持全员追忆等社群玩法
  - (c) 本地剧本的保存/复制/删除

### Could（v2）

- **F-15 战绩** — 玩家数据库与统计（局数、胜率、队友/克星关系）— 依赖 F-06 流水，数据模型 v1 即须兼容
- **F-16 捏角色** — DIY 角色编辑器（自定义角色 + 图标）
- **F-18 工具箱** — 私聊记录等主持杂项（v2）

**F-17 旅行者** — 旅行者/传奇/奇遇支持（v1 Must，ADR-009）
- (a) 旅行者座位：中途加入、阵营计算排除、死后阵营可转（手动）
- (b) 传奇/奇遇以“非抽袋角色”入魔典（不占构成）
- (c) 夜单含旅行者/传奇/奇遇的黄昏行动

**F-19 备忘** — 夜晚信息记录（v1 自由文本，v2 结构化）
- (a) v1：快捷模板“座位号【角色名】___”填空，存为 note 事件；不依赖角色库，天然支持 DIY（ADR-010）
- (b) v2：官方角色结构化信息格式（占灯师→是/否、侍女→数字）；预留自定义字段 `infoTemplate` 供剧本作者声明（DATA-MODEL 待登记）
- (c) 战报按座位聚合全部备忘

**F-20 声称** — 玩家声称记录（v1）
- (a) 座位声称的角色 + 声称发动的能力/获得的信息（自由文本）
- (b) 与实际角色并列显示，复盘对比“谁跳了什么”
- (c) 事件类型 `claim`，承载于 F-06 流水

**F-22 换位** — 座位操作（v1，ADR-011 锚号）
- (a) 换位：原子交换两座位全部住户字段（女舍监），编号与位置不动
- (b) 增/删座位：旅行者中途进出；新号 = max+1，删后退役不重用；displayOrder 支持任意排列（1 2 3 4 15 5 6…）
- (c) seat_swap / seat_add / seat_remove 事件入 F-06 流水

**F-21 计时器** — 说书人计时器（v1）
- (a) 白天讨论计时（默认 10 分钟可调）、辩护计时（默认 30 秒）
- (b) 到时提醒（震动/声音，手机友好）；不持久化，杀后台重置可接受

### Won't（明确不做）

- ❌ 线上联机/房间系统（那是官方 app 的地盘，也违反 TPI 政策精神）
- ❌ 玩家账号系统、服务端存储（local-first 是架构红线）
- ❌ 自动规则判定/角色交互裁决（TPI 明确禁止"提供权威裁决"的工具；歧义是游戏设计的一部分）
- ❌ 应用商店上架（TPI 政策禁止）
- ❌ 付费、广告、众筹

## 4. 非功能需求

- **N-01 内地可用**：主站自部署 + 静态镜像；首屏 < 200KB gzip；一次加载后离线可用
- **N-02 移动优先**：说书人多用手机/平板；交互以触控为先
- **N-03 可测试性**：`src/lib/` 纯函数覆盖率 > 80%；主链路（导入→分配→过一夜→导出）有 e2e
- **N-04 版权合规**：AGENTS.md 版权红线全部满足
